# 原版检查与修复记录

| 原问题 | 修复与影响 |
| --- | --- |
| 将 brand 整包当作 UTF-8，再删除标点；忽略 VarInt 字符串长度 | 严格读取 VarInt + UTF-8，校验长度、异常编码、控制字符、最大长度，不改变合法标点 |
| 保存或当前品牌为 unknown 就跳过校验；空保存 IP 也跳过匹配 | 缺失/未知/损坏品牌或空 IP 均拒绝自动登录 |
| 先注册现代通道失败后，旧通道注册也被同一个 catch 跳过 | 按服务端版本选择旧/新通道，Paper 优先读取公开客户端品牌 API |
| 延迟不足时尚未收到品牌，按 unknown 直接放行 | 有限等待品牌，超时要求手动登录 |
| 加入、lookup、remove 等在主线程执行阻塞 SQL | 持久化操作全部进入容量有限的数据库工作队列；回调切回主线程 |
| 异步保存任务访问 Player 在线状态、地址与品牌 | 在主线程抓取不可变快照，数据库线程不访问 Bukkit 玩家对象 |
| forceLogin 是异步处理，调用后立即提示成功 | 仅在 AuthMe LoginEvent 后提示；调用失败不提示成功 |
| 自动登录也收到 LoginEvent，刷新保存时间 | 区分本插件的待登录请求，自动登录不延长原凭证 |
| 已离线/重连的旧异步结果可能仍作用于玩家 | 回调检查原连接对象，不能作用于相同 UUID 的新连接 |
| 主动 logout/注销/改密未撤销旧凭证 | 监听 AuthMe logout、双方注销事件及常用改密命令；删除同时取消在线待登录请求 |
| SQL 保存失败仍写缓存，删除失败却报告成功 | 成功写入数据库后才写缓存；异常清缓存并暂停自动登录；命令按真实结果回复 |
| 并行保存与删除乱序，关服先关闭池 | 同一实例的数据库任务串行处理，连接池在任务队列处理完后关闭 |
| 每小时缓存一次“今日零点”，跨日失效可能延迟 | 使用 Clock + ZoneId 按自然日直接判断 |
| max_time=0 提前返回，连未来时间和跨日也放行 | 0 只关闭时长限制，无效/未来时间与跨日检查始终有效 |
| 仅排除 IPv4 127.0.0.1，遗漏 IPv6 和其他回环地址 | 按 InetAddress 检查回环、未指定及多播地址；IP 解析仅接受字面值，不进行域名查询 |
| 数据库驱动未随插件提供，依赖其他插件偶然提供 | 运行库放入 plugins/AutoLoginAuthme/libs，按固定 SHA-256 校验，缺失或损坏时自动下载，独立类加载器隔离加载 |
| Hikari 实际打包 SLF4J 2.0 API 却配 1.7 binding | API 与 JDK logging binding 统一为 1.7.36，隔离加载测试覆盖 |
| JDBC 使用 characterEncoding=utf8mb4 | 使用 UTF-8，保留 MySQL 表 utf8mb4 字符集 |
| 建表错误只打日志，继续启动 | 建表失败传播并停止启动，关闭刚创建的连接池 |
| 玩家名大小写分别缓存，旧大小写记录不一致 | Locale.ROOT 统一缓存键；兼容查询旧记录，事务保存时规范化 |
| 负缓存容量、0监控间隔、无效连接池配置可造成异常 | 配置统一校验范围与类型，重载失败继续使用原运行配置 |
| reload 只改静态字段，未更新连接池/监控 | 新连接校验后切换完整运行组件，旧读写队列结束后再启用新组件 |
| 直接调用五参数标题方法，旧 API 缺失 | 反射选择五/双参数标题方法，失败回退聊天栏 |
| 各职责挤在同包，使用大量全局静态字段 | 拆为职责包与不可变数据，生命周期显式释放，无全局插件单例 |
| 将第三方依赖合入主 JAR，不便查看和单独维护 | 参考 MistralLobby 使用外置 libs，主 JAR 仅包含插件代码；构建生成完整离线部署 ZIP |
| 外置类加载器可能在数据库任务结束前关闭，或遗留 JDBC 清理线程 | 等初始化及数据库队列结束，停止本加载器的 MySQL 清理线程、注销 JDBC 驱动、释放资源缓存后关闭加载器 |
| Hikari 按驱动类名加载时可能经线程上下文选择其他版本的 MySQL 驱动 | 显式创建独立加载器内的 MysqlDataSource，再交给连接池；加入父环境已有同名驱动且线程上下文为父加载器时的回归检查 |
| MySQL 认证失败时只有异常堆栈，缺少配置修正提示 | 对错误码 1045 / SQLState 28000 输出服务端配置位置及需检查的账号、密码、权限，保留原始异常供排查 |

## 保留的兼容行为与限制

- 继续使用原 MySQL 表名与时间单位，保留常用配置键和管理命令。
- 默认拒绝 OP 自动登录；无凭证时保持 AuthMe 正常手动认证。
- 本方案没有设备私钥，无法将客户端品牌当作强指纹；详见 README 中的安全边界。
- 原版会话中被错误清洗的品牌可能与真实品牌不同，升级后可能需要重新手动登录一次。
- 改密命令监听在命令执行前撤销，无法知道 AuthMe 最后是否修改成功；这是缺少统一事件时的保守处理。其他接口改密需额外同步撤销。
